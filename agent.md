## 🚀 1. Executive & Architectural Overview

* **Project Name**: `kmstech-app` (`kmstech-next`)
* **Legal Entity**: KMS Tech (*Trade License: TRAD/DNCC/131256/2022*)
* **Primary Domain**: `https://kmstech.co`
* **Headless Host**: `kmstech.hashnode.dev`
* **Architecture Paradigm**: Next.js 16 (App Router) hybrid architecture:
  1. **Client SPA Shell (`/[[...slug]]`)**: Interactive single-page interface with state-driven modal dialogs (`About`, `Services`, `Concerns`, `Contact`, `Blog`) animated via GSAP and custom vector graphics (`MainLogo.tsx`, `SVGLayer.tsx`, `TopQuote.tsx`).
  2. **Headless SSR Blog (`/(blog)/blogs`, `/(blog)/blog/[slug]`)**: Server-side rendered pages powered by Hashnode GraphQL API with 60-second Incremental Static Regeneration (ISR).
  3. **Atomic Persistence Layer**: PostgreSQL database managed via Prisma ORM 6.x tracking view statistics with composite key `[type, slug]` and SWR optimistic UI synchronization.
  4. **Automated OG Screenshot Worker**: Headless Puppeteer script generating 1200x630 high-DPI Open Graph previews (`scripts/generate-og-images.ts`).
  5. **PWA & Offline Resilience**: Progressive Web App integration using `next-pwa` with automatic service worker registration and real-time offline detection (`OfflineIndicator.tsx`).

## 🗄️ 4. Data Layer & Prisma Database Specification

### Prisma Schema (`prisma/schema.prisma`)
```prisma
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

model Stats {
  type      String   @default("blog")
  slug      String
  views     Int      @default(0)
  loves     Int      @default(0)
  applauses Int      @default(0)
  ideas     Int      @default(0)
  bullseyes Int      @default(0)

  @@id([type, slug])
  @@map("stats")
}
```

### Prisma Client Singleton Pattern (`src/lib/prisma.ts`)
```typescript
import { PrismaClient } from '@prisma/client';

const globalForPrisma = global as unknown as { prisma: PrismaClient };

export const prisma =
    globalForPrisma.prisma ||
    new PrismaClient({
        log: ['query'],
    });

if (process.env.NODE_ENV !== 'production') globalForPrisma.prisma = prisma;
```

### REST API Route Handlers (`src/app/api/view-count/[slug]/route.ts`)
* **`GET /api/view-count/[slug]`**:
  - Queries `prisma.stats.findUnique({ where: { type_slug: { type: 'blog', slug } } })`.
  - Returns JSON `{ views: stats?.views ?? 0 }`.
  - On DB failure, logs a warning and gracefully falls back to `{ views: 0 }`.
* **`POST /api/view-count/[slug]`**:
  - Executes atomic upsert: `prisma.stats.upsert({ where: { type_slug: { type: 'blog', slug } }, update: { views: { increment: 1 } }, create: { type: 'blog', slug, views: 1 } })`.
  - Returns JSON `{ views: stats.views }`.
  - On failure, returns HTTP status 500 `{ error: 'Failed to increment views' }`.

### Frontend SWR Hook (`src/hooks/useViewCounter.ts`)
* **State Management & Deduplication**:
  - Fetches current count via SWR from `/api/view-count/${slug}`.
  - When `increment()` is called:
    1. Checks `localStorage.getItem('viewed-' + slug)`. If present, aborts immediately to avoid duplicate counting.
    2. Sets `localStorage.setItem('viewed-' + slug, 'true')` synchronously (guards against React 19 / Strict Mode double invocations).
    3. Performs **optimistic update**: `mutate({ views: (data?.views || 0) + 1 }, false)`.
    4. Triggers background `POST` request to `/api/view-count/${slug}`.
    5. Revalidates SWR on completion. If POST fails, clears `localStorage` key and rolls back state via `mutate()`.

## 📡 5. Headless CMS Integration (`src/lib/hashnode.ts`)

* **Endpoint**: `NEXT_PUBLIC_HASHNODE_ENDPOINT` (default: `https://gql.hashnode.com`)
* **Target Host**: `NEXT_PUBLIC_HASHNODE_HOST` (default: `kmstech.hashnode.dev`)
* **Auth**: Optional `Authorization: Bearer ${HASHNODE_ACCESS_TOKEN}`
* **Revalidation**: Custom fetch transport passing `next: { revalidate: 60 }` (60s ISR cache window).
* **Exported Data Models**:
  - `Author`: `{ name, username, profilePicture, bio?: { html, markdown, text } }`
  - `Post`: `{ id, title, slug, brief, publishedAt, updatedAt?, readTimeInMinutes, coverImage?, author, content: { html, markdown?, text? }, tags?, views }`
  - `PostsResponse`, `SinglePostResponse`, `PageInfo`
* **Exported API Functions**:
  1. `getAllPosts(cursor?, accumulatedPosts?)`: Recursively traverses cursor pagination (`pageInfo.hasNextPage` / `endCursor`) returning `{ posts: Post[], totalDocuments: number }`.
  2. `getPosts(page = 1, limit = 6)`: Fetches all posts via `getAllPosts()`, applies offset slicing (`(page - 1) * limit`), returns `{ posts, totalDocuments, hasNextPage, endCursor: null }`.
  3. `getPost(slug)`: Queries single post payload via `GET_POST_QUERY`.

## 🎨 6. UI & Design System Architecture

### Core Design Tokens (`src/app/globals.css`)
* `--primary-green`: `#009444`
* `--text-color`: `#e0e0e0`
* `--bg-dark`: `#020408`
* Font Families:
  - `--font-geist-sans`: Geist (Google Font)
  - `--font-geist-mono`: Geist Mono (Google Font)
  - `--font-atkinson`: Atkinson Hyperlegible (Google Font)
  - `'Segoe Print'`: Custom local `@font-face` mapped from `/fonts/segoepr.ttf`

### Key Animation Systems
1. **Logo Path Drawing (`MainLogo.tsx`)**:
   - Calculates total SVG path lengths via `getTotalLength()`.
   - Initializes `strokeDasharray` and `strokeDashoffset` equal to total length.
   - GSAP timeline animates `strokeDashoffset` to 0 with 0.05s stagger, transitions `fillOpacity` to 1 and `strokeOpacity` to 0.
   - Replays animation on click.
2. **Dynamic Background Turbulence (`SVGLayer.tsx`)**:
   - Renders SVG filter `#grunge-texture` containing `<feTurbulence>`.
   - GSAP continuously animates `baseFrequency` from `0.65` to `0.66` over a 10s `sine.inOut` yoyo loop.
3. **Glowing Text & Attribution (`TopQuote.tsx`)**:
   - Dual-layer paragraph structure: Base Layer + Glow Layer (`position: absolute`).
   - Uses multi-stage `text-shadow` gradients (#63ff33, #25b42c, #ff3c009d, #ff44008c, #ff000088).
   - Container has a continuous subtle floating motion (`y: -10`, 4s duration, `yoyo: true`).

## 🤖 7. Automation Scripts & Pipelines

### OpenGraph Screenshot Generator (`scripts/generate-og-images.ts`)
* **Execution**: Run with `npx tsx scripts/generate-og-images.ts`.
* **Prerequisites**: Local dev server running at `http://localhost:3000`.
* **Behavior**:
  1. Fetches all posts via `getAllPosts()`.
  2. Launches Puppeteer in headless mode (`width: 1200, height: 630, deviceScaleFactor: 2`).
  3. Checks if screenshot `/public/og-images/${slug}.png` exists and is present in `src/data/og-map.json`. Skips existing images.
  4. Navigates to `http://localhost:3000/blog/${slug}` with `waitUntil: 'networkidle0'`.
  5. Confirms hydration by waiting for `h1` element.
  6. Takes PNG screenshot, saves to `public/og-images/${slug}.png`, and writes update to `src/data/og-map.json`.
